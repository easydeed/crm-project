# OR-012 — Job runner and send safety gate

```
TASK: OR-012
BRANCH: feat/job-runner

OBJECTIVE
A job runner that can drive the monthly send, and a hard block that
makes it impossible to email a real homeowner before the S2 gate passes.

WHY
S4 needs five idempotent jobs and a cron tick. Without a runner and a
send-enabled gate, compose/send work would ship without a kill switch.

SCOPE
- src/jobs/ — runner, registry, locking, enqueue, send-guard
- POST /api/cron/tick (CRON_SECRET → 404 when wrong/missing)
- vercel.json cron every minute
- Minimal read-only /admin/jobs
- jobs.payload_key + unique index for duplicate enqueue
- Out of scope: composing, Postmark, unsubscribe flows, full admin
  monitor (OR-013 to 015). Do not merge until Director APPROVED.

BACKOFF (acceptance wins over prose schedule)
Prose listed "1m, 5m, 30m, 2h, then dead" (four delays → five runs).
Acceptance says "dead after four attempts." BUILD_PLAN does not
specify delays. Implemented: four attempts then dead; gaps between
attempts 1→2, 2→3, 3→4 are 1m, 5m, 30m. The 2h delay is unused
because dead-after-four leaves only three gaps.

DESIRED BEHAVIOR
1. Runner claims with SELECT … FOR UPDATE SKIP LOCKED; abandoned
   locks (>15m, no completed_at) are reclaimable. Handlers idempotent.
2. Five kinds registered with stubs; send stub calls assertSendAllowed
   and never sends mail. SEND_ENABLED stays false in committed code/CI.
3. enqueue(kind, payload, runAfter); unique on kind + payload_key +
   run_after (payload_key = sha256 of canonical JSON).
4. Cron tick runs up to N due jobs; wrong/missing secret → 404.
5. assertSendAllowed requires SEND_ENABLED=true, allowlist (or '*'
   in production), not unsubscribed, account not paused.
6. /admin/jobs read-only; agents 404; four states; ≤300 lines.

ACCEPTANCE CRITERIA
1. Two concurrent runners never claim the same job
2. Throw → retry on backoff, dead after four attempts
3. Abandoned lock claimable after 15 minutes
4. Duplicate enqueue → one row
5. Cron route 404 without correct secret
6. assertSendAllowed throws under default env, every send path
7. Throws for domain outside allowlist
8. Throws for unsubscribed contact and paused account
9. Same stub handler twice → identical state
10. /admin/jobs renders; agents 404
11. pnpm verify passes; open PR; CI green; DO NOT MERGE

DO NOT
- Send any email
- Set SEND_ENABLED true in committed code or CI
- Add a queue service or a dependency
- Delete job rows
- Change PROJECT_STATE.md, CLAUDE.md, BUILD_PLAN.md, ca-tax.ts
- Merge without Director APPROVED
```
